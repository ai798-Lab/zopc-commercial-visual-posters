# ZOPC商用运营视觉海报

把真实样张、形象和活动信息分开选择，制作具有统一三维潮玩质感的运营海报。形象编号为 M01–M10，样式编号为 S01–S11；两者独立组合。样张中的角色只是搭配示范，不能覆盖用户选定的角色。

从本 SKILL.md 所在目录解析所有相对路径。若能执行 Python，运行 `python3 scripts/catalog.py mascots` 或 `styles` 获取当前安装位置下的真实图片绝对路径；也可直接读取 [catalog.json](references/catalog.json)。

迁移或安装后可运行 `python3 scripts/verify_assets.py` 核对素材完整性；它只检查文件与目录，不替代视觉审稿。

## 交互流程

保留用户已经提供的信息，从尚未完成的步骤继续；用户已给出形象、样式和文案时直接制作，不把全部选择重新问一遍。

1. **选视觉形象。** 新调用先显示 `assets/galleries/mascots.png`，简短列出 M01 柴犬、M02 熊猫、M03 机器人、M04 柯基、M05 奶牛猫、M06 兔子、M07 棕熊、M08 企鹅、M09 水獭、M10 小恐龙；提供“自定义：上传图片或文字描述”入口。只问选哪个形象。已有明确选择就跳过。自定义形象的物种、轮廓、颜色及用户明确要求优先，参见 [角色与自定义](references/characters.md)。C01 小象是自定义示范，不算第十一个预设。
2. **选样式。** 形象确定后，实际展示 `assets/galleries/styles-01.png` 和 `styles-02.png`，保留 S01–S11 编号与名称。简述差异，请用户选择样式；需要看大图时显示所选 `assets/styles/Sxx.png`。说明图中不同角色用于展示搭配，最终采用用户已选形象。只回复“3号”时按当前正在选择的步骤解读；上下文不明确就只澄清是 M03 还是 S03。
3. **收集对应信息。** 样式选定后，按 [信息单与渠道](references/intake-and-channels.md) 一次给出简短填写单：用途/平台与尺寸、主标题、主要利益点、必要时间地点、售价或权益（如需）、一个行动引导、品牌/Logo和二维码要求。先读用户已给的资料，只补缺项；无价格、无日期、无Logo都是有效选择。用户要求先看概念时，可用明确标为演示的精简文案，不能伪造正式活动事实。
4. **制作。** 查看所选样式图和形象母版。按 [制作规范](references/production.md) 构图、配字、检查。图片创作和局部编辑优先使用现有内置 image_gen；不默认切到要 API Key 的脚本。样式参考只约束视觉，角色参考约束身份，新活动信息约束文字。复杂中文/金额可另排可编辑文字；Logo和可用二维码使用真实原文件。可运行 `python3 scripts/poster_brief.py validate brief.json` 检查信息，`prompt brief.json` 输出生成任务与正确参考路径；脚本不会替用户生成图片。
5. **检查与交付。** 逐字核对文案，查看原图及手机尺寸，检查物种、手爪、光影、卡片透视、文字居中、Logo边距，以及本次明确要求的权益元素。二维码必须解码对照用户当前原码；无法核验时如实说明。保存新版本，展示海报并给出绝对文件链接，简述改动和实际验证。不能把生成完成叫作平台已发布。
6. **询问是否延展。** 首张完成后，用一句自然的话询问：“要不要沿用这个形象和样式，继续做详情页、权益图、直播预告、倒计时或横版封面？”只有用户选择了延展才制作对应内容。延展保留形象身份、字效角色、配色和Logo基准，按新比例重新布局。用户起初已授权整套，则按该范围完成后再询问追加项目。

- [原有问题与修整](references/quality-fixes.md)：本套真实问题及处理方法。
- [运营视觉十维检查](references/visual-standard.md)：按本次载体选用，不强制所有活动同一配色。
